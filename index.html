01

O modelo

GLM-5.3 é o modelo topo de linha da Z.ai (Zhipu), lançado em 18/08/2026. Ele usa a mesma arquitetura-base do GLM-5.2 — praticamente todo o ganho vem de pós-treino em escala (RL), não de um modelo novo. É o modelo de open weights mais capaz para código segundo a própria Z.ai, com +50% sobre o GLM-5.2 no benchmark interno Z.ai Code Bench.

Os pesos são abertos (licença estilo MIT com condição de revisão de segurança para MaaS > US$10B de receita), com checkpoints FP8 e BF16 no Hugging Face — mas o GLM Coding Plan é outra coisa: uma assinatura por créditos que dá acesso a GLM-5.3 e GLM-5.3-Flash em endpoints dedicados, sem cobrança por token.

Por que ele importa

Agentic coding de longo alcance. Os maiores saltos sobre o GLM-5.2 estão exatamente em tarefas longas de agente: SWE-Marathon mais que dobrou (19,4 → 42,5), DeepSWE subiu de 46,2 para 66,9 e Terminal-Bench 3.0 foi de 4,6 para 28,3. Ele mantém um plano através de centenas de passos de terminal sem perder o fio.

Capacidade emergente em segurança. Na CyberGym (descoberta de vulnerabilidades) é o melhor resultado publicado até aqui (84,5), e nos benchmarks de exploração supera o GLM-5.2 por mais de 2×.

Economia de tokens. Nos evals internos, o GLM-5.3 entrega mais acerto com menos saída: no esforço máximo, 34,5% com ~75K tokens de saída por tarefa, contra 23,4% com 96K do GLM-5.2.

Raciocínio sempre ligado. Não existe modo “sem thinking”: os níveis são low · high · max (padrão: max). Pede-se desabilitar? O request falha — por design.

* Total/ativo estimados pela Artificial Analysis; a Z.ai não publica os parâmetros oficiais. Fontes: docs.z.ai · model card no Hugging Face

03

Como ele trabalha de forma agêntica

GLM-5.3 não é um chatbot que responde — é um modelo pós-treinado para loops longos de ferramenta: planejar, chamar tool, observar, corrigir, repetir. Os próprios evals da Z.ai rodam com harness de agente real (Claude Code 2.1.207), e é assim que ele opera dentro do Hermes.

01

Reasoning nativo em três esforços

Cadeia de raciocínio sempre ativa, com reasoning_effort low (leve), high (reforçado) e max (profundo, o padrão). O Hermes traduz a preferência da sessão para esse vocabulário automaticamente. Modo “sem pensar” não existe no 5.3 — quem pede recebe low.

02

Function calling como cidadão de primeira classe

Ferramentas, streaming de chamadas, saída estruturada (JSON) e contexto de 1M tokens. Nos runs independentes do Coding Agent Index, o modelo sustentou ~107 passos por tarefa com 97% de acerto de cache — o caching de contexto é o que torna loops longos economicamente viáveis.

03

Horizonte longo sem perder o plano

Benchmarks como SWE-Marathon e Terminal-Bench 3.0 medem exatamente isso: sessões de horas, até 600 turnos, refatoração de repositórios inteiros. Foi onde o 5.3 mais cresceu sobre o 5.2 (+119% em SWE-Marathon).

04

Memória em camadas (do lado do agente)

O modelo em si não guarda estado entre sessões — quem memora é o harness. A própria Z.ai documenta o padrão: memória de sessão (contexto), de projeto (CLAUDE.md / regras), semântica (RAG), episódica e procedural. No Hermes isso é nativo: skills, memória persistente e arquivos de projeto cumprem exatamente essas camadas.

05

Roteamento transparente no plano

No endpoint do Coding Plan, pedidos por GLM-5.2/5.1 são roteados automaticamente para GLM-5.3, e GLM-4.7 para GLM-5.3-Flash. Verifiquei na prática: pedir glm-4.6 retorna "model": "glm-5.3-flash". O plano só fala esses dois idiomas.

04

Browser use

O fato central: GLM-5.3 é texto puro. Entrada e saída são texto — ele não enxerga screenshots. As features de computer use e browser use da Z.ai rodam no GLM-5.3-Flash, o modelo multimodal que acompanha o plano. Na prática, a dupla funciona assim:

No Hermes, browser é dirigido por DOM, não por visão. As ferramentas de browser do Hermes (navegar, clicar, preencher, ler página) trabalham text-first: leem o DOM via JavaScript e devolvem texto estruturado para o modelo decidir o próximo passo. Isso casa perfeitamente com um modelo text-only — o GLM-5.3 navega por estrutura (seletores, accessibility tree, coordenadas calculadas) sem precisar “ver” a tela. Foi assim que ele construiu e publicou esta página.

Quando a visão é necessária, o plano inclui. Todos os planos do Coding Plan têm o Vision MCP Server da Z.ai (npx @z_ai/mcp-server), que roda no GLM-5.3-Flash e dá ferramentas como ui_to_artifact (screenshot → código), extract_text_from_screenshot (OCR), diagnose_error_screenshot e leitura de diagramas e dashboards. O plano também inclui Web Search, Web Reader e Zread MCPs.

Division of labor que funciona: GLM-5.3 decide, planeja e escreve; Flash enxerga quando há pixel envolvido. No meu setup os dois estão a um comando de distância (/model glm-code ↔ /model glm-code-flash).

Regras de ouro

!1

Nunca o endpoint padrão

api.z.ai/api/paas/v4 cobra do saldo da conta mesmo com plano ativo. Só o /api/coding/paas/v4 consome cota do plano.

!2

Só dois modelos

O plano cobre GLM-5.3 e GLM-5.3-Flash; qualquer outro pedido é reescrito para um deles.

!3

Créditos: janela de 5h + semanal

Lite 2.000/10.000 · Pro 12.000/60.000 · Max 28.000/140.000 créditos. Fórmula: (in×6,9 + cache×1,7 + out×24)/10.000 para o 5.3; Flash ~3× mais barato. Fora do horário de pico (dia de semana 14h–18h SGT) tudo custa 50% — fim de semana inteiro é meia cota.

!4

Verificação periódica

grep -o "api.z.ai/api/[a-z/]*" agent.log | sort | uniq -c → só deve aparecer coding/paas. E o dashboard da Z.ai mostra cota (não saldo) caindo.
